# Experiment maintenance timer

The user authorised an autonomous check every 30 minutes to unblock experiments and test E00–E04. A local Python timer invokes one noninteractive Codex maintenance agent now and then at 1800-second intervals, with a 25-minute worker timeout and a singleton file lock. Factory daemons and supervisors remain separate; the worker may resume or start appropriately identified trials without keeping its own turn waiting for them. Each invocation uses the installed Codex default model and existing login, separate from factory-run accounting.

This is a workspace-local process, not a hosted ChatGPT reminder. It continues after this chat turn while this workspace remains awake; it cannot wake a suspended container or send proactive chat notifications. If restarted after workspace shutdown, run `python3 tools/experiments/maintain.py` in a detached process, after checking the recorded PID and lock. Do not launch duplicate timers.

Read `timer.json` for last/next check and PID, `latest.json` for the latest check-in, `progress.json` for durable experiment progress, and `checkins/` for each worker's structured answer, stderr and event log. Logs are ignored; secrets must not be copied into them. Cadence timestamps use UTC, while chat reports use Europe/Dublin. To stop future checks create `docs/experiments/tetris-007/maintenance/STOP`; to stop the current maintenance worker as well, send SIGTERM to the PID in timer.json. The timer terminates its worker on shutdown, leaving factory runs alone.

The [maintenance instructions](../../../../tools/experiments/maintain-prompt.txt) preserve failed observations, original acceptance and one-variable comparisons; permit targeted repairs and labelled resumptions/new cohorts; avoid repeated immediate provider retries; and require a combined ledger for all hypotheses. Workers cannot silently relax acceptance or change factory models/providers. Final evidence includes uncached input/output, cache-read/write coverage, corrections/recovery and product acceptance. The timer stops after all five hypotheses are tested, or when a non-transient blocker requires user input. Worker errors and transient quota failures are logged and rechecked on the next tick.

The worker uses the installed `codex exec` command and structured final output, following the [official iterative repair-loop example](https://developers.openai.com/cookbook/examples/codex/build_iterative_repair_loops_with_codex). Source and command options were verified locally before enabling this timer.
