Proposed machine instruction changes

Keep the 13 task boundaries. Apply these directions to the doer and planner, then measure a fresh run with the same acceptance coverage.

1 · Read the current contract

Read the seed, global requirements, completion rule, and task headings. Read the first unfinished task in full, including every acceptance clause and subtask. Open other task bodies only for dependencies; locate relevant source and tests with targeted searches.

2 · Keep a compact handoff

Explicitly read and maintain a short file of source/test locations, behavior decisions, verification commands, known pitfalls, and unresolved work. Update it within the task’s change and confirm relevant facts against the working tree. The seed and plan stay authoritative.

3 · Recover existing work

Inspect repository status and current-task changes before editing. Verify and finish valid work left by an interrupted attempt; preserve unrelated changes. Stay on that task through retries until every acceptance check passes.

4 · Reuse verification recipes

Run focused checks during editing and the full suite after the final change. Keep successful output concise, inspect full failure diagnostics, and rerun when new edits invalidate evidence. Capture game frames via the entry point or silent npm; retain the actual npm start PTY check.

5 · Narrow planner updates

Locate the committed task by its exact result name. Read and update only that task and its completed subtasks, then scan every task/subtask marker for remaining work. Reopen code or repeat verification only when the result is ambiguous. Mark work done only after the factory commits it.

6 · Keep results concise

Give brief progress updates, then finish with one standalone JSON object containing the exact task name and concise verification evidence. Avoid repeating the implementation narrative. Keep the bridge boundary fix: extra prompt wording alone is not reliable transport protection.

Acceptance stays intact: preserve every task’s edge cases and automated checks, the 24-row display budget, full-suite verification, and task 13’s falling → locking → line clear/score → game over → restart → quit regression.
