Hypothesis
before reading

If the responsibility-driven lens influenced 002, it should replace 001’s central, state-exposing game object with cohesive collaborators, exchange intent-revealing messages, and create test seams around terminal I/O and time—not merely add classes.

Evidence from the code

1

Knowledge moved to its owner

001’s TetrisGame owns board storage, tetromino definitions, bag selection, collision, clearing and scoring. In 002, Board answers placement and clears lines; immutable Piece objects move/rotate; PieceSource owns the bag.

2

State inspection became messages

The 001 renderer reads the game’s board, dimensions, score, lines, level and game-over flag. In 002, displaySnapshot() creates a deliberate read model and render(snapshot) knows nothing about Game.

3

Collaborators became replaceable

002 injects board, piece source, input, renderer, scheduler and cancel function into Game. Its test harness substitutes all external effects. By contrast, 001’s tests directly overwrite board and game state, while startup closes over real timers and process signals.

4

Messages express intent

002 translates byte sequences once, in TerminalInput, then tells the game left, rotate or drop. The 001 entry point combines raw-key parsing, command dispatch, gravity, drawing and shutdown in one 113-line function.

Counter-evidence / remaining cost

Game.handleAction() still switches on action strings, and Game owns timing, scoring, lifecycle and dispatch. Also, 002 grows from 418 to 499 source lines (+19%). The lens produced clearer boundaries, not less code or full polymorphism.

Conclusion

The important difference is not “more objects.” 002 gives each volatile concern a home and makes collaboration observable and substitutable. That matches the lens closely; the remaining action dispatcher is small enough that extracting a command hierarchy now would be speculative.
